# DT-09 — Infraestructura de demo con costo $0 (free tier)

- **Estado**: Aprobada
- **Fecha**: 2026-09-24
- **Sprint**: 1 (T-S1.07)
- **Relacionado**: EC-10 (costo de la demo = $0), `docs/07-calidad-y-seguridad.md`

## Contexto

EVENTIVO debe demostrarse al Ingeniero con trazabilidad completa (ciclo Juan
Pérez) **sin gasto operativo**. Toda decisión de hosting/proveedor debe caber
en el free tier del proveedor elegido y ser reproducible (Infrastructure as
Code o procedimiento documentado).

## Decisión

Se despliega la demo sobre los siguientes free tiers (2026):

| Componente | Proveedor / servicio | Free tier usado |
|---|---|---|
| Código + CI/CD | GitHub | Repositorio público (o privado con Actions 2000 min/mes) |
| Bases PostgreSQL | Supabase | Un proyecto free: 500 MB BD + API PostgREST (no usada por ahora) |
| API (microservicios) | Render | Web Services gratuitos (0,1 CPU / 512 MB, duermen por inactividad) |
| App móvil (APK demo) | GitHub Releases | Distribución del APK de debug |
| Notificaciones | Firebase Cloud Messaging | Gratuito (límites de uso razonable) |
| DNS + TLS | Render / let's encrypt | Subdominio `*.onrender.com` con HTTPS automático |

### Cómo encajan las bases de datos

- **Local/desarrollo**: 5 contenedores PostgreSQL 16 vía Docker Compose
  (`docker/docker-compose.dev.yml`, puertos 5432–5436), esquema por servicio.
- **Demo/producción**: **un solo proyecto Supabase free** con 5 bases de datos
  (auth_db, evento_db, asistencia_db, notificacion_db, reporte_db). El límite
  de 500 MB es suficiente para el volumen de la demo.
- Cada servicio apunta a su base vía variable `DATABASE_URL_<SERVICIO>`
  (GitHub Secrets, ver `README.md` raíz).

## Alternativas consideradas

1. **Railway / Fly.io** — free tiers más restrictivos o con tarjeta requerida; descartados.
2. **Neon (serverless Postgres)** — interesante (branching, 0.5 GB) pero añade un
   proveedor más; Supabase centraliza BD + auth de respaldo, más simple para la demo.
3. **Vercel para APIs (serverless)** — los servicios NestJS con TypeORM/pg no se
   adaptan bien a funciones serverless sin reescritura; Render hostea el proceso
   tal cual (NestJS estándar).

## Consecuencias

- **Positivas**: costo total = $0 (EC-10); despliegue reproducible con secrets
  documentados; migración de Render/Supabase a otro proveedor es solo cambiar
  variables de entorno (URLs) porque los servicios son estándar NestJS + pg.
- **Negativas**: los servicios free de Render **duermen** tras inactividad
  (primer request tarda ~30–60 s); Supabase free pausa el proyecto tras 1 semana
  sin actividad — mitigado con alertas de actividad del Ingeniero y `README` con
  el procedimiento de "despertar".
- **Riesgo**: superar límites free en demo concurrida → mitigación: rate limiting
  en gateway (Nginx) y cupos máximos de la propia app.

## Criterios de aceptación

- [ ] El costo mensual de la infraestructura de la demo es $0.
- [ ] Todos los secrets requeridos están documentados por *nombre* en el README raíz.
- [ ] El procedimiento de despliegue está en el README raíz / docs.
